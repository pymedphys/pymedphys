# pseudonymise — State Model

The pseudonymise app ([lib/pymedphys/_streamlit/apps/pseudonymise.py](../../lib/pymedphys/_streamlit/apps/pseudonymise.py)) is a single-page Streamlit tool that accepts a list of DICOM files via `st.file_uploader`, pseudonymises each one in place using `pymedphys.experimental.pseudonymisation`, packs the results into one or more ≤ 50 MByte zip files, and offers them as base64-encoded data-URL download links in the sidebar. This document is the canonical labeled-transition-system translation of that script, generated by the `python-streamlit-state-model` skill: the Prolog DCG models the script's rerun semantics as a 5-state user-receptive LTS layered over a 4-stage internal-trace pipeline, with widget events and side-effect labels forming the two interleaved streams of the [ALGT MUZAQ pattern](https://d/MUSIQ/ALGT/README.md).

This is the **first reference deliverable** produced under the `python-streamlit-state-model` skill. Future Streamlit-LTS translations (notably `metersetmap`) should look here for canonical structure.

## 1. Primary State Machine

**5 user-receptive states**, **4 user event terminals**, **12 side-effect-stream label families**.

![Primary State Machine](diagrams/stm_primary.svg)

> Source: [`diagrams/stm_primary.puml`](diagrams/stm_primary.puml)

The state machine has two-tier semantics, distinguished load-bearingly:

- **User-receptive states** (5): `init`, `idle_no_files`, `idle_files_uploaded`, `displaying_results`, `error_bad_data`. The script has finished a rerun and is waiting for the next widget interaction. **Each user event triggers one rerun, which is one transition between user-receptive states.** Bisimulation is done at this level.
- **Internal-trace states** (4): `computing_chunking`, `computing_per_chunk(I, N)`, `computing_per_file(I, J)`, `computing_zip_assembled(I)`. Visited *within* a single rerun's compute transition. Observable as partial-render artifacts (the `st.write(index_to_fifty_mbyte_increment)` at [pseudonymise.py:173](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L173) is the user-visible signal that the LTS is past `computing_chunking`), but **not user-event-receptive** — the user cannot click anything mid-`computing_per_chunk(3, 10)` and have the script resume from there.

The decision to keep `init` and `idle_no_files` as separate user-receptive states, rather than collapsing them, is deliberate: their *prior history* differs (init has no chunk-results in the DOM; idle_no_files may have stale `sidebar.links` from a previous compute). The state-dict's `sidebar` and `main` slots distinguish them.

The decision to keep `error_bad_data` as a first-class state, rather than a transient modal, mirrors the cs-ui-state-model rule that user-visible error renders are first-class states. The user can interact with the page (uploading more files, clicking the button again) while the error text is visible; that interaction is a transition out of `error_bad_data`.

## 2. State Dict Schema

### 2.1 Schema diagram

![State Dict Schema](diagrams/bdd_state_dict.svg)

> Source: [`diagrams/bdd_state_dict.puml`](diagrams/bdd_state_dict.puml)

The state{} dict has 8 top-level slots. `session{}` and `caches{}` are empty for this app — pseudonymise.py uses neither `st.session_state` nor `@st.cache_*`. The remaining slots are: `tier` (the discriminating LTS state atom), `widgets{}` (Streamlit widget-keyed cache), `compute{}` (in-flight pipeline pseudo-state), `sidebar{}` and `main{}` (rendered DOM accumulators), and `rerun_count` (monotonic trace bookkeeping).

**Key insight (rerun-vs-persistent partition):** Streamlit reruns the script top-to-bottom on every widget event. After a rerun, only `widgets`, `caches`, and `st.session_state` survive in the runtime; local function variables vanish. This LTS additionally tracks `compute` (in-flight pipeline state visited within a single transition) and `sidebar`/`main` (the rendered DOM accumulated across reruns) as pseudo-state for trace fidelity. `session` and `caches` are empty because pseudonymise.py uses neither — this is why the schema is unusually flat compared to `metersetmap` or any cs-ui-state-model deliverable.

## 4. Per-Rerun Pipeline

![Per-Rerun Pipeline](diagrams/act_rerun_pipeline.svg)

> Source: [`diagrams/act_rerun_pipeline.puml`](diagrams/act_rerun_pipeline.puml)

Streamlit's rerun pipeline has 4 phases for this app: widget render (top of `main()` — `st.file_uploader` + `st.button`), event dispatch (the `if st.button(...):` branch + the implicit upload/clear branches), compute (the `pseudonymise_buffer_list` body, summarised here as a single repeat-block), and render (the chunk-index `st.write`, the per-chunk `st.sidebar.markdown` calls, and the error-branch `st.text`).

The pipeline is **mostly linear**: each rerun walks Phase 1 → Phase 2 → optionally Phase 3 → Phase 4 → output. The optional Phase 3 (compute) only runs if the button was pressed AND files are present. Otherwise the pipeline short-circuits at the end of Phase 2 and the rerun produces only widget renders.

## 5. Compute Pipeline

![Compute Pipeline](diagrams/act_compute_pipeline.svg)

> Source: [`diagrams/act_compute_pipeline.puml`](diagrams/act_compute_pipeline.puml)

The compute pipeline is the body of the `click(pseudonymise_button) [files_present]` transition. It decomposes into 5 sub-phases visible at trace level (the internal-trace states):

1. **Entry** ([compute_ops.pl:run_pseudonymise_pipeline/2](prolog/compute_ops.pl)) — timestamp the basename, transition to `computing_chunking`. Side effects: `datetime_now`, `datetime_strftime`.
2. **Chunking** ([chunk_index_list.pl:compute_chunks/2](prolog/chunk_index_list.pl)) — pure compute; produces `[end_index_1, end_index_2, ...]`. No side effects.
3. **Render chunk indices** ([render_ops.pl:render_chunk_indices/2](prolog/render_ops.pl)) — `st.write([...])` to the main page. Side effect: `st_write(indices)`.
4. **Per-chunk loop** — for each chunk index: open zip BytesIO (`bytesio_new`, `zipfile_open_write`); per-file inner loop (`pydicom_dcmread` → `anonymise_dataset` → `build_pseudonymised_filename` → `pydicom_dcmwrite` → `zipfile_writestr` → `bytesio_close` for the per-file BytesIO); on success: emit download link (`bytesio_getvalue` → `base64_b64encode` → `st_sidebar_markdown` → `bytesio_close` for the per-chunk BytesIO); on exception: print + render error text + break out of both loops.
5. **Terminal** — set `tier := displaying_results` (or `error_bad_data` if any chunk had `bad_data == true`).

**Translated phases**: 1, 2, 3, 4, 5 (all in `compute_ops.pl` + `render_ops.pl`).
**Boundary primitives** (Phase 4's per-file core): `pydicom_dcmread`, `anonymise_dataset`, `pseudonymisation_dispatch`, `pydicom_dcmwrite`, `zipfile_writestr` — all in `streamlit_boundary.pl`. The algorithm-kernel ones (`anonymise_dataset`, `pseudonymisation_dispatch`) cross-reference the deferred `python-algorithm-verification/anonymise/` deliverable.

## 6. Domain Constraints and Invariants

![Constraints and Invariants](diagrams/par_invariants.svg)

> Source: [`diagrams/par_invariants.puml`](diagrams/par_invariants.puml)

### 6.1 Constraints

#### `files_present_gate`
**Predicate:** `browse_ops:files_present/1` ⇔ `len(widgets.dicom_uploader) > 0`. **Anchor:** [PY:163](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L163). **Effect on fail:** the `click(pseudonymise_button)` transition becomes a no-op (the `pseudonymise_buffer_list` helper short-circuits at PY:163 before calling `_gen_index_list_to_fifty_mbyte_increment`). Tier stays `idle_no_files`. The button widget-state still resets True → False (edge-trigger).

#### `valid_dicom_file`
**Predicate:** implicit in `compute_ops:pseudonymise_one_file/4`'s `catch/3`. The DICOM file must successfully `pydicom.dcmread`, must allow `anonymise_dataset` to run without raising `KeyError`/`OSError`/`ValueError`, and must allow `pydicom.dcmwrite` to serialise the mutated dataset back. **Anchor:** [PY:114, :118-125, :129, :130-134](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L114). **Effect on fail:** `compute.bad_data ← true`; inner per-file loop breaks ([PY:134](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L134)); outer chunk loop breaks (preserved in the LTS by `compute_ops:process_chunks_loop/4`'s early return); tier transitions to `error_bad_data`; `render_error_text` emitted. **No partial success is preserved** — chunks completed before the failing chunk DO have their links emitted to the sidebar, but the failing chunk's partial zip BytesIO is closed without emitting a link.

#### `chunk_size_under_threshold`
**Predicate:** `chunk_index_list:compute_chunks/2`'s eager-split logic. **Anchor:** [PY:222](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L222) (`if size > 50000000`). Not actually a fail-mode — the compute splits chunks eagerly when the running size accumulator exceeds the threshold. The accumulator is reset (not the chunk position), so a single oversized file lands as the trailing element of one chunk, and the next chunk starts fresh. **Edge case preserved verbatim:** a single uncompressed file exceeding 50 MByte will produce a single-file chunk that may exceed the data-URL download cap; the docstring at [PY:152-155](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L152-L155) calls this out explicitly.

### 6.2 Invariants

#### `tier_widget_consistency`
`state.tier == idle_no_files` ⇔ `widgets.dicom_uploader == []`. Re-applied by `browse_ops:derive_idle_substate/2`, called from `widget_ops:upload_dicom_files/3` and `widget_ops:clear_dicom_files/2` after they update the widget cache. The `displaying_results`/`error_bad_data`/`computing_*` tiers do not enforce this invariant on `widgets.dicom_uploader`'s contents — those tiers reflect *what was computed*, not *what is currently uploaded* — but they do require it to be non-empty at entry (verified by the `files_present` guard).

#### `compute_chunks_partition`
The sum of file sizes across all chunks equals the total upload size: `Σ I (size of slice [chunks[I-1]:chunks[I]]) == Σ (file.size for file in widgets.dicom_uploader)`. Held by `chunk_index_list:compute_chunks/2`'s construction, where every file is consumed exactly once and assigned to exactly one (possibly trailing partial) chunk. **Anchor:** [PY:217-228](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L217-L228).

#### `sidebar_links_match_completed_chunks`
`len(sidebar.links) == count(I : 0..chunk_count where computing_zip_assembled(I) was reached without bad_data)`. Held by `render_ops:render_download_link/4` only being called on the success branch of `compute_ops:process_chunk_inner/5`. **Anchor:** [PY:195-197](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L195-L197). Note this allows partial success: if chunks 0, 1, 2 succeed and chunk 3 fails, `len(sidebar.links) == 3` AND `tier == error_bad_data`.

#### `error_isolation`
When `state.tier == error_bad_data`: `main.error_text_rendered == true`, AND no further compute or render mutates session/widgets/compute (until the next user widget event). Held by `compute_ops:process_chunks_loop/4`'s early return on `bad_data == true`. **Anchor:** [PY:133-134, :187-193](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L133-L134).

#### `edge_triggered_button`
Across two consecutive reruns, `widgets.pseudonymise_button` transitions True → False exactly once between any two click events. Streamlit's button widget is edge-triggered: it returns True only on the rerun immediately following the click, then False. Held by `widget_ops:pseudonymise_button_click/2`'s last clause (which writes False back). **Anchor:** Streamlit semantics, verified at the `st.button` call site [PY:239](../../lib/pymedphys/_streamlit/apps/pseudonymise.py#L239).

#### `no_session_state_usage`
`state.session == _{}` for every reachable state. Held by every `step//2` rule (none touch `state.session`). **Anchor:** the absence of any `st.session_state` reference in `pseudonymise.py` (verifiable via `grep "session_state" lib/pymedphys/_streamlit/apps/pseudonymise.py` → empty result).
