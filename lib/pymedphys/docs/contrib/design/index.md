# Design documents

Design documents explain the intended behaviour, constraints, and rationale
behind substantial changes. Read their implementation status before treating a
proposed interface or supported input as available. The requirements register
and release evidence establish which parts of the de-identification design
are implemented and validated for a stated scope.

The DICOM de-identification design is organised into an overview,
specification, decision record, requirements and evidence, and contributor
tasks. A change to a decision updates its implementation, tests, and affected
user guidance together.
